# Mac 键盘完成态与原接收进程边界

本修复解决真实应用的辅助功能接口暂忙、已完成输入被后续AX读取错误判失败，以及原进程退出后旧按键责任无法归还的问题。新Down仍要求完整的当前窗口、焦点、权限、输入代次和租约证明；已完成的配对则独立确认身份、原输入责任与系统按键状态，不将一次AX暂不可读当作重新输入的理由。

## 实现边界

- AX暂忙只在原500ms共享准备预算内等待；每个新字符不能续期，单次完整证明及让出执行的上限保持。等待之后、真正发送之前，再同步检查精确进程／窗口身份与取消围栏。
- 已发Down的配对Up保留原Unicode、虚拟键与修饰信息，只向原PID／出生实例发送。原接收者已退场时，只有当前会话已确认且该键没有按下，才以零发送解除这次责任；身份或按键状态未知则保持阻止，不向后继实例补发。
- 配对结束后检查原owner、held登记、系统按键、权限与光标恢复状态。动作未知或部分完成不重放，下一次Down仍重新取得完整证明。
- 透明Dock区域仅在独立核实系统Dock文件身份、对应layer和实际点的公开命中测试确实指向精确目标窗口时排除；其他覆盖窗口继续阻止输入。
