# 验收模板、再次运行与版本对比（H6）

本功能在现有自动验收卡片增加“验收模板”入口。用户明确保存当前清单为模板或新清单版本；在模板库选择版本并点击“再次验收”，请求通过公开 Session API 进入当前会话，由当前主 Agent 使用已有工具执行。用户无需关联聊天、重新选择环境或重复批准仍然有效的“始终允许”。

## 实际契约

- 模板持久数据只有名称、说明、不可变清单版本、预算和当前配置文件内的运行引用。不保存环境、目标、画面、控制句柄、输入、租约、应用/站点授权、图片或验收结论。
- 每次创建新 workflow；H3 开始时创建新 run。保存模板或提交聊天请求不会启动设备操作。工具调用新 ID、主 Agent 实物身份与当前授权仍由真实 Host 检查。
- 模板形成新草稿和运行引用持久化完成后，Host 记录当时实际模型环境的最后观察帧。开始前必须经过一次新的真实观察，并与 H3 确切捕获的环境、目标、epoch 对齐。仍合法的服务、环境和 epoch 可以复用；不要求无意义的 epoch 变化、关闭浏览器或人为重授权。
- 新观察来自 H2 的可信模型目标注册表；切换或查看 UI 画面不会改变它。模型、Owner RPC 和模板文件均不能传入 start prerequisite、旧帧或权限对象。
- H3 原清单编辑 CAS、有限修复授权、预算、取消、未知 ACK 和 H1 独立校验规则保持。每个检查使用新的真实证据。模板没有通过/失败写入接口。
- 对比只读取本会话已链接的真实 H3/H1 记录。显示原失败及后续尝试，不重跑动作；条件变化的检查明确标记为不可直接比较。旧通过不传给新版本；尚未运行、证据缺失、未知结果均不能显示为新通过。

## 当前会话与提交收据

模板库使用公开 ResourceProvider、sidebarRightTabs 和 slots。聊天卡片打开当前会话的资源；视图本身只读，不写模型目标、控制租约或应用状态。模板在当前 Host 配置文件内可复用，但运行引用按当前聊天过滤，不能借共享模板读取其他聊天的结果。

“再次验收”通过真实 `SessionBinding.session.beginSubmission` 和 `session.prompt(..., 'queue', signal, requestId)` 发送一次普通用户请求。只有同一个当前 binding/session、提交前序列之后、文本与随机提交编号完全一致的 `user/message` 且来源为 `user` 才确认“已出现在当前会话”。队列接受不等于验收开始或通过。结果未知不自动重发；当前插件生命周期内该会话的未知提交保持阻止重复按钮派发；只有随后同一真实 binding/session 的公开历史补齐了那份精确耐久用户消息，下一次明确按钮请求才可解除该阻止。此核对不重发原请求。用户也可在原会话核对记录。正常已送达后，可以再次明确验收同一个模板/同一个版本，不要求改变版本号。

## 存储、升级与撤销

使用独立的 `qiuya-tools-acceptance-templates/v1` 私有目录，最多32模板、每模板16清单版本/64运行引用、每文件512KiB、目录8MiB。文件有完整哈希、固定路径、链接/目录身份检查、CAS 和原子提交；每个异步边界继续验证原 owner/Agent。旧清单版本和运行引用只能追加，不能覆盖；撤销为不可清除的墓碑，不删除旧结果。旧 H3-only 配置直接新增该目录，不改原 H3/H1 文件；同格式重启重读保留版本和撤销，不能恢复旧草稿的执行能力。未知 schema 保留文件并拒绝解释，不自行迁移或删除。

撤销意图进入持久化前先在 Host 当前生命周期阻止模板使用；写盘未知或 Owner 变化时不宣称成功，也不恢复旧草稿。新模板准备的运行引用提交未知时，已创建的 H3 草稿保持未武装，不能自行开始；同一个工具 callId 不重新准备。所有旧失败和未知尝试保留。

## 公开能力评估：调度、日常浏览器与 H7

本次检查的是项目已安装的公开 `@deepseek-ai/*@0.2.1-rc.2` 导出与实际代码，不是对所有宿主版本的能力推断。

- 已具备公开 Session submission、当前主 Agent 工具、Workspace 状态/会话归属、资源、侧栏标签和 H1/H3 历史查询。本功能直接复用，不创建新的模型循环、会话系统或 IDE。
- 当前已安装依赖集合未包含可确认的持久调度/自动化或 terminal/editor controller 导出。不能由此断言其他宿主版本不存在；后续必须先核对真实宿主已注册接口、任务身份、取消及持久收据，再在用户明确创建计划时启用。H6 不建立定时器任务、cron 或后台日常自动运行。
- 浏览器支持已有专用 profile/显式环境配置，但这不构成日常个人浏览器 profile 的授权或归属证明。再次验收使用当前仍合法的专用服务；不扫描、复制、连接用户日常 profile，不自动接管已有登录态。扩展/日常 profile 连接需要独立的公开连接能力与明确授权证据，本次只评估。
- H7 优先让当前主 Agent 继续使用宿主已经提供的代码、文件和终端工具；插件只负责现有电脑与证据通道。当前公开集合不足以确认新的 IDE/终端嵌入协议，所以没有重造编辑器、终端或账号体系。

## 验证范围

代码、有效测试和生产参数的 `write:false` 构建在独立普通临时副本完成，不修改 live、Git、native 或 lib，不启动真实 Host/Chrome/GUI/PD/模型/系统输入。测试包括真实 Cordis/ToolRuntime/HostConnectionService、真实 H1/H3/模板私有文件存储、公开 Session API 合同和 React/JSDOM。设备、会话事件来源使用明确隔离 fixture；这些测试不冒充双平台视觉或真实模型验收。

正常项目类型检查、Host/Session/核心 React 的真实公开 SDK 严格检查分别记录。完整侧栏 wrapper 的严格检查若受到当前已安装 SDK 闭包中缺失依赖声明影响，会保留并单列库级诊断，不使用 `any`、声明替身或放宽模式来制造通过。最终集成后仍需 Root 对新安装包执行 Mac/Windows 真实界面与模型验收，并继续遵守64MiB安装包门槛。

## 宿主真实观察的新鲜度

模板准备完成后，以宿主进程单调 issued-observe 序号作为边界，不能仅比较所选 frameId。只有真实 ComputerSessionService 的模型 observe 调用开始时才取号；成功完成校验并匹配当前 epoch/target/frame 后，保存到以实际 service 对象为键的私有 WeakMap。模板从 ModelTargetRegistry 的真实选中服务读取该映射，不接受 model/RPC/driver/frame DTO 自填序号。

预览、自动 resume、仅切换已有缓存目标不会取号；prepare 之前开始、之后才完成的 observe 也不越过准备边界。新的真实 observe 可在相同合法 environment、target 与 epoch 使用，已有“始终允许”授权保持。服务 dispose 清除对应映射，进程序号不重置；MAX_SAFE_INTEGER 耗尽会拒绝新观察，不能环绕或重用旧号。所有帧/序号都只用于当前宿主内存围栏，不存入模板或继承控制句柄。
