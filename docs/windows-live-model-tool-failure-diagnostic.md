# 真实工具失败有限诊断（仅测试载体）

本单元保持原模型、工具、授权和成功条件，只改验收载体的有限诊断与日志写入。生产插件、原生程序和交付安装包没有变化。

## 保存实际拒绝，继续传播原错误

ARM 80327956 的三个业务任务、图片、核验码、预算和最终清理均通过，但 task1 第五个工具记录为 `qiuya_computer_act isError:true`，因此原整轮仍失败。旧记录只有 `unclassified`，不能唯一判断是模型参数、产品拒绝还是原生返回。

现在在原失败 catch 保存实际公开 ComputerError 白名单码、固定 operation 和 SDK callId SHA256。165项白名单来自当前生产 `tools.ts` 的公开错误合同，来源 SHA 绑定；没有公开码时仍为 `unclassified`。原异常对象继续抛出，不保存原始消息、堆栈、参数、账号、图片或 AX 正文。已有状态诊断次数和1000毫秒门保持。

原 carrier 转发同一请求/响应时最多保存32条不可覆盖的 `native-rejection-NNN.json`，仅含原 numeric requestId、白名单 op 和错误码。没有原生失败回复时不生成 requestId，不增加 native RPC、输入、截图或重试。诊断保存失败不能替代原业务错误。

## 观察性日志不阻塞关键回执

阶段日志继续使用私有目录、0600独占临时文件、完整写入与关闭、不可覆盖的原子发布，并等待这些步骤完成。只有观察性阶段日志移除每事件 `FileHandle.sync`；授权、输入issued记录、协议回执、ready和最终报告的原耐久写入均不变。没有完整写出的日志不会发布；存储错误仍能使载体失败，不会重放已执行命令。

真实文件系统回归分别验证诊断不调用sync、通用协议回执仍等待真实sync、部分写入不发布、存储失败时零命令、执行后保存失败时恰好一次命令、已存在文件与符号链接拒绝、2048条上限。
