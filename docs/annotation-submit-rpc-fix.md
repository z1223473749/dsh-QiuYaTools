# 批注提交与公开错误协议修复

Windows 实际批注验收发现，发送前的画面核验可能与每 500 毫秒的轮询并发。两次读取共用同一冻结画面，后到的读取会改变 Host 的序号，使仍然有效的最终核验被拒绝。另有六个公开接口的错误响应缺少 SDK 必需的 `details` 字段，客户端把具体错误显示为 `connection: invalid server-response failure`。

本次修复让同一编辑器的画面检查、元素命中与样式读取顺序执行。开始生成批注图后停止周期轮询；已发出的读取先完成，再执行一次新的最终核验。如果先前读取确认画面失效、聊天变化或用户取消，则不发送消息。保留原有 15 秒上限、目标归属、画面版本和未知结果不重发的边界。

批注、工作台、验收清单、验收模板、网页诊断和任务记录的失败响应统一补齐 `details: {}`，并用官方 `ConnectionRpcFailure` 类型检查。用户仍能看到接口规定的中文提示，原始异常文本不进入响应。

## 验证

- 真实公开 Connection 客户端经过 HTTP Request、实际 Host 路由及 SDK 解析器，验证六路错误响应均可识别，不泄露原始异常，也不重试设备操作。
- 使用受控异步读取复现轮询和最终核验的竞态，验证顺序、取消、聊天变化、真实失效和禁止重复提交。
- 896 项相关回归、36 项专项、正常类型检查及七套真实 SDK 严格类型检查通过。
- 精确新候选的 156 个测试文件共 1962 项直接测试通过，失败、取消、跳过均为零。源码及正式产物在测试前后保持一致。
- 三个生产 JS 入口按正式配置构建，164 项输入校验通过；Mac universal、Windows ARM64、Windows x64 三包均通过正式包校验、成员哈希和原有 64 MiB 限制。原生组件字节保持不变。

完整测试首次运行发现两个环境／旧测试问题：隔离副本缺少历史安装包样本，以及插件加载测试仍期待已经被工作台取代的聊天标题栏槽位。补入原哈希的历史样本，并将加载测试改为核验实际公开侧栏服务的可选注入，再完整重跑通过。原始失败记录保留。

本单元的新 Mac／Windows 批注界面复验另行记录，不继承旧包的视觉结果。Windows 原轮五项通过、提交失败的证据也保留。
