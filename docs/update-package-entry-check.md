# 更新包的公共入口校验

更新包原先可以通过包名、版本、patch 与原生组件校验，却缺少实际 Host 入口。这样的包能够被预检接受，安装后仍无法加载。一次隔离构建的输出路径错误暴露了这个问题；不完整包随后被独立 Host 加载校验拒绝，没有安装。

现在归档预检要求 `lib/index.js` 和 `lib/client.js` 存在且为非空普通文件。已声明 `qiuyaNative.protocolVersion=1`、`computerUse=true` 的包还必须包含非空 `lib/computer-agent.js`。历史 0.5.2 没有电脑代理入口，仍可通过预检用于升级和回滚。

原有 64 MiB 归档限制、tar 成员类型和路径检查、重复及大小写冲突检查、patch、原生协议、架构、长度和 SHA 校验继续生效。入口存在性检查不替代独立加载与配置 schema 验证。

## 验证

- 归档、Windows 平台和更新 Host 相关回归 19/19 通过。
- 六个真实平台／历史归档组合继续通过，包含真实 0.5.2、Mac universal 开发候选和 Windows 双架构候选。
- 十三个此前会被旧校验器接受的不完整真实 tgz 派生包被新校验器拒绝，包含首次误构建产物，以及缺失、为空、目录代替文件和大小写替换的公共入口。
- 八个既有重复、大小写及平台身份边界继续拒绝，未通过放宽原规则换取兼容。
- 合并后的工作区完成 typecheck 和 104 个测试文件、1027/1027 项直接回归；源码与受保护产物在这轮检查期间保持稳定。该总数包含其他正在独立实机验收的改动。

实际归档矩阵和完整测试原始报告分别保存在项目外验收目录与本机忽略的 `artifacts/computer-use/final-direct-test-suite/7b0a7901-8b4e-487c-adef-a5e050a240d7/report.json`。这些开发检查没有启动个人 Host、模型、GUI 或桌面输入。
