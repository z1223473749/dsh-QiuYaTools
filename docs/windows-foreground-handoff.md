# Windows 多会话的前台交接

同一个 Harness Host 为两个聊天分别启动原生执行器时，A 操作后的前台资格不会自动交给 B。此前即使 FIFO 已确认 A 释放鼠标和键盘，Windows 仍可能拒绝 B 激活目标窗口。本次修复让 A 在一次已完成、已清理的操作之后，只向当前 Host 的精确 B 执行器交接前台资格；实际输入仍由原来的目标授权、观察、物理租约和原生输入检查决定。

## 行为与绑定

仅支持声明该能力的 Windows 本机执行器。Mac、旧组件和远端通道保留原有路径。不同 Host 或管理器不互相发现，也不交接资格。

每次操作先准备一张 2 秒内必须开始使用的票据，绑定目标、观察几何、动作摘要、聊天周期、原生周期、桌面代次和物理输入序号。A 的成功操作完成且输入清理确认后，才生成一次性的交接凭据。凭据最多保留 300 秒，容纳现有真实模型请求预算；等待期间发生人工输入、桌面变化、停止或执行器失效都会使旧资格失效。该期限不会延长 B 的 2 秒动作票据。

交接两端必须具有相同的 Host 父进程身份、执行文件路径与 SHA、架构、登录会话和桌面。原生层重新读取 PID、进程出生时间、路径、文件 SHA 和父进程身份，并持有精确进程句柄直到调用完成。A 同时确认自己的目标仍在前台、系统没有按下的键或鼠标、共享输入租约空闲、journal 不存在，再调用一次 `AllowSetForegroundWindow(B.pid)`。

这里没有使用 `ASFW_ANY`、模拟 Alt、`AttachThreadInput`、额外点击或重放失败动作。交接失败或回包未知时，本次动作失败；Host 不会为了获取前台资格再次发送业务输入。

Windows 的前台资格属于进程，不能等同于可撤回的单张应用票据。因此，执行器第一次进入票据控制后，即使票据取消或过期，后续操作仍必须持有一张新的对应票据，不能退回无票据路径。

## 取消与收尾

已经写出的 prepare 请求即使遇到暂停，也要接收其成功回包，登记并精确取消实际生成的 ticket。身份或回执格式校验失败时，有合法 ID 就取消该 ID；无法识别副作用身份时停止该执行器，保留结果未确认错误。

成功 release 回包中的交接凭据必须有明确归属。只有操作成功、当前聊天周期仍有效、桌面代次和物理输入序号未变化，才可发布为下一次交接来源。操作失败、暂停或收尾期间发生人工输入时，精确取消旧凭据。原始操作错误和清理错误分别保留。

一旦尝试交接，即使 Windows 拒绝或原生端在校验后报错，Host 也不能再次使用旧来源凭据。清除只针对仍为同一对象的旧记录，避免迟到的收尾擦除其他新记录。

## 当前验证范围

隔离构建已通过 typecheck、122 项 Host／调度／真实 JSONL／工具错误投影回归，以及直接使用生产状态机的 71 项原生核心行为测试。Windows ARM64 与 x64 自包含程序均完成 locked restore 和 publish。

新增覆盖包括 prepare 成功回包晚于暂停、精确取消失败、身份不匹配、回包未知、动作失败后 release、物理输入发生在收尾 await 期间、已消费凭据不能再次发布或重用、300 秒来源期限与独立 2 秒动作票据。真实 JSONL 用例启动本地测试子进程，不代表 Windows 原生桌面已通过。

两架构平台包均已在隔离目录构建并通过原更新包校验及64 MiB限制。与H6整合后的ARM64包为58,070,212字节，x64包为62,321,453字节，分别剩余9,038,652与4,787,411字节；后续增加功能继续检查实际归档大小。

本文件记录实现与已完成的开发检查。新原生程序的 PD 默认多会话、实际 FIFO、弹出／收回预览、同一按住区间的系统状态与物理截图验收仍须单独记录；旧组件的视觉或真实模型通过结果不继承到新组件。

## 2026-10-24整合构建与实际范围

本单元包含17个前台交接产品和测试文件，与已提交H6在同一独立快照构建。218项相邻回归全部通过，正常类型检查、公开Host及ClientCore严格检查通过。当前完整工作区586个源码文件的157个测试文件另完成1976项直接回归，无失败或跳过；该范围包含当时明确保存的其他工作区开发文件。测试期间源码和正式lib均未变化。

三入口生产JS的164个实际输入逐项匹配暂存树或外部依赖，三个归档通过正式校验、空目录Host加载与原64 MiB限制。原生复用a38c/873c，Mac保持8f47/bb0d；原生构建来源29项完整保存在独立来源副本，主项目package.json只有测试脚本差异，版本及原生构建配置相同，没有把它写成当前29项逐字相同。最终整合归档为Mac `4eb5a1ec`、Windows ARM64 `33191c36`、Windows x64 `b79a6724`；完整SHA由交付报告保留。
