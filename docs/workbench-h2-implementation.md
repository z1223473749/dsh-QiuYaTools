# H2 工作台实现与集成说明

本说明对应第 16 节的 H2 核心工作台接线。2026-10-24 已从精确暂存代码制作独立快照，完成构建、相关回归和 Mac 真实 SDK 七项闭环；Windows 对应界面、真实 DeepSeek、浮窗视觉优化及下列专项继续执行，不替代原生 A–F 基线。

## 用户流程

开启电脑操控后，直接在会话中提出网页或软件任务。原生应用继续使用既有应用授权与系统权限引导。网页任务使用本会话的独立 Chrome/Edge 环境；首次访问一个网站来源时，聊天里显示“允许一次、始终允许、拒绝”。允许前不启动该浏览器或截取内容。其他来源须单独授权；原生 Chrome 应用授权不隐含所有网站授权。

聊天中常态只显示 300×180 满幅小框、边框与阴影。鼠标悬停或键盘聚焦时显示控制按钮；小框只能在当前窗口内移动。用户可选择要预览的当前会话任务并弹出公开 SDK 工作台。工作台支持浏览器和桌面视图、多标签、浮动、收回及分栏；标签和面板布局由 Harness 公开 SDK 管理。隐藏视图仅取消读取，继续保留任务。

在工作台中，暂停、接管、继续、停止分别复用原有控制状态。接管后的点击、拖动、滚动、文字与导航均使用实际显示帧；按住鼠标时不让轮询的新帧替换这次手势。前进、后退、刷新及关闭网页只在用户已接管时发送；“新网页”是用户明确允许一次或持续许可的动作。导航到另一来源仍受授权检查。关闭网页、停止任务、退出浏览器环境和隐藏视图互不代替。

## 权威与身份

- 聊天来自真实主 Agent 对象或 owner RPC 的公开会话查询，模型参数不能声明聊天或 owner 身份。
- 浏览器由 `BrowserWorkbenchRegistry` 按聊天及浏览器种类管理独立 profile；它与原生 `ComputerEnvironmentManager` 共同组成 `WorkbenchRegistry`。每次工具调用捕获确切 service、Agent 对象、environment/view/target/appId、generation 和 epoch。不会通过当前 UI 标签或同名标题路由。
- UI 切换、展开、隐藏、停靠、分栏及预览不会修改模型目标。模型通过 open/select/observe 明确选定执行目标。浏览器上下文失效时，H1 不回退到原生环境补证。H1 仍限同一 environment/target，跨目标检查继续保留为证据不足。
- owner RPC 在读取 body 前绑定确切 connection、peer、principal、request signal 和 provider lifetime；每个读取与设备 await 前后复验。公开 `sessionQuery.observeSession(..., projectionMode:'none')` 只读 header 并释放 lease；它证明请求时该逻辑会话存在，不宣称持续侦测已删除的历史会话。独立 session signal 若由 scope 提供，会传给 driver。
- 预览只返回白名单图片与几何、目标和 AI 指针元数据，AX 文本为空。AI 指针只投影确认的 AI 状态；CDP 通道不声称移动系统物理指针。原生专属指针和系统权限路径保持既有实现。
- 未确认输入的 actionId 不可重放；human RPC 有 1024 次 Host 生命周期发出记录上限。迟到授权只回滚该次 once 来源；持续许可撤销先同步封锁、再持久化，保存失败也不能恢复输入。

## 生命周期与失败

浏览器缺失且运行时被证明确实为空时，正常后续请求可以重新检查安装；未知启动保留原运行时和错误，不另起实例。启动取消、超时及自然退出超时均不发送终止信号，也不丢失尚未退休的自有子进程。显式退出环境通过 `Browser.close` 和原 5 秒自然退出门确认；未知结果保留清理所有权，等待用户关闭或之后显式复核。

工具注册中途失败会逆序回滚已注册工具；一个 disposer 失败不会跳过其他清理。安装失败和正常卸载均聚合错误，不把“未确认清理”写成成功。关闭功能会使现有输入和 once 能力失效，重新开启不会自动恢复旧控制。

## 可重复的离线检查

```bash
npm run typecheck
npm run typecheck:workbench:host
npm run test:workbench
```

`typecheck:workbench:host` 使用真实已安装 SDK 类型，`strict:true`、`skipLibCheck:false`，覆盖工具、Host 接线与实际 composite/coordinator 的兼容性。客户端常规严格检查和生产参数 `write:false` 构建通过；客户端整个第三方声明闭包仍有 SDK 缺失声明诊断（例如 lexical、layout、mdast、katex），单独保存，不添加伪 SDK 声明或将其计为全 UI canonical 类型通过。

单元测试使用真实 ToolRuntime/Cordis、React/JSDOM、Request/ReadableStream 和既有 ComputerSessionService，并为设备和附件服务提供有限合成夹具。它们不启动浏览器、Host、原生程序、PD 或模型；dummy 图片只验证传输、归属和交互边界，不属于视觉通过截图。

4. 固定满幅小框、阴影、hover/focus 控件、窗口内拖动、浅深色/缩放；工作台接管下点击、拖动、滚动、输入及实际导航，验证未知 ACK 不重放。
5. 真实 DeepSeek 使用实际六个 browser 工具完成有限流程；H1 证据必须来自本次真实 service/目标/版本，不由模型文字直接给通过。
6. 自然停止、关闭环境、功能关闭与卸载的原输入/lease/子进程退休检查。任何失败轮保留原始事实；截图和完整报告继续放在项目外目录。
