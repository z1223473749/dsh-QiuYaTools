# 电脑操控兼容性

## 权限兼容

Windows 普通模式会在输入前读取目标完整性级别。高权限目标返回 `administrator-required`，不会把权限失败等同于窗口失效或自动重发。

用户先停止现有控制，再在电脑操控的系统权限区域选择“启用管理员访问”，并在目标 Windows 桌面确认 UAC。独立助手只开放状态、应用发现、观察、租约和输入；应用启动、任意命令及网页预览不进入提权进程。主界面和网页预览继续使用普通权限。

提权通道使用同一用户的随机命名管道，双向核验进程身份。取消 UAC 不改变普通模式。切换后需重新观察和获取控制；安全桌面、跨用户提权和受系统保护的目标不承诺可控。普通和提权助手共用桌面锁；输入日志允许正常的跨权限交接，守护进程继承输入所有者权限。退出必须确认提权助手已释放输入，否则保持故障状态。

验证：TypeScript 类型检查、权限入口与原生协议测试、生产提权传输的独立 .NET 行为测试、Windows ARM64 编译。传输测试不产生系统输入。真实 UAC、跨权限桌面输入和异常恢复仍需 Windows 交互环境验收。

## 虚拟输入与真实输入授权

所有原生应用统一默认使用窗口内的后台控件操作，不按 Chrome 或其他应用名称切换真实输入。macOS 和 Windows 的虚拟指针同时显示在任务预览和目标窗口可见位置，使用不接收点击、不获取焦点的独立透明窗口；它跟随 AI 的操作坐标，不跟随或隐藏系统鼠标，目标位置被其他窗口遮挡时不显示。暂停、停止、切换目标或释放控制时清除指针。Windows 使用不激活窗口的透明指针层；原生租约在单次动作后释放时保留任务的虚拟位置和文字锚点，只有暂停、停止、目标切换或逻辑任务释放才清除，避免连续“点击→输入”丢失目标。

macOS 使用辅助功能接口，支持可用的按钮、浏览器标签、文本和离散滚动。Chromium 标签栏存在重叠的结构容器时，沿所有命中分支查找唯一可操作控件；多个实际控件重叠仍拒绝执行，不凭子节点顺序猜测。文本锚点必须具有文本控件角色和实际文本值，不能仅凭“属性可写”把结构容器当作输入框。Windows 的 UI Automation 仅用于读取控件，写入限定为标准 HWND 按钮和编辑框的定向窗口消息，其他控件、滚动和拖动返回不支持，避免旧版 UIA / MSAA 提供程序隐式激活窗口。虚拟路径不调用全局鼠标、键盘事件，不主动激活窗口、修改全局焦点或隐藏系统指针，AI 的虚拟租约不持有桌面输入锁。普通用户输入不撤销虚拟租约。

不支持的操作在发出输入之前返回 `VIRTUAL_INPUT_UNSUPPORTED`。独立的 `qiuya_computer_request_physical_input` 请求绑定当前任务、目标身份、控制周期和具体失败动作。只有用户选择“允许本次真实鼠标操作”后，Host 才能向执行器传递私有的单次真实输入许可。此许可不能放进模型的动作参数，不继承应用持续授权，不能授予其他动作；批准后旧观察帧失效，暂停或停止也会撤销许可。实际操作失败或结果未知不会自动重放。

控件变更已经投递但结果不明时返回 `VIRTUAL_INPUT_UNCONFIRMED`，保留暂停和人工确认边界，不能将其当作未执行来申请真实鼠标重放。本机、调度、路由和远程链路均保留同一授权标记。缺少 `virtualInput` / `virtual-input` 能力声明的旧执行器不能取得原生输入租约或执行动作。

虚拟输入验收脚本：`node scripts/test-macos-virtual-input.mjs`。它仅创建自有后台窗口，不申请系统权限、不投递全局键鼠事件。2026-11-03 实测后台按钮连续 5 次点击与文字输入成功，系统指针、前台应用不变，测试窗口未激活。当前环境不能读取前台应用的 AX 详细焦点，报告将其标记为未验证；不能据此宣称任意第三方应用均已验收。2026-11-04 Windows x64 实机使用当前原生执行器、会话服务和授权协调器完成验收：标准 WinForms 后台按钮 5 次点击与文本写入成功，系统指针、前台 HWND、键盘焦点 HWND、剪贴板序号和全局注入计数不变；目标激活和焦点事件均为 0。后台再点击 60 次时，前台正常输入完整保留。虚拟拖动先返回不支持，独立卡拒绝时真实调用为 0；用户单独批准后仅执行 1 次真实拖动，重试恢复虚拟拒绝，拒绝下一张卡后真实调用仍为 1。证据见 `artifacts/computer-use/windows-virtual-input-2026-11-04-final/`，执行器 SHA-256 与本地构建一致。Windows ARM64 仅编译，未实机运行；该验收不覆盖任意第三方控件。

macOS 已打开浏览器标签的定向验收：`node scripts/test-macos-browser-tab-virtual.mjs BROWSER_BUNDLE_ID EXACT_TAB_TITLE REPORT_PATH`。脚本只切换明确指定的现有标签，验证虚拟指针坐标、桌面指针显示状态、释放清理、系统鼠标、前台应用、键盘焦点和剪贴板；焦点不可读时在报告中明确标记。它不创建浏览器、不请求真实输入授权。2026-11-04 Chrome 收录 PR 标签的实测证据见 `artifacts/computer-use/macos-browser-virtual-2026-11-04/report.json`；此项不代表 Windows 浏览器标签或任意第三方控件已经通过验收。

## 可选的浏览器任务标签组

标签分组是独立的可选增强。Chrome/Edge 配套扩展已连接时，使用浏览器原生标签组显示当前任务的操作目的；未安装、未连接或分组不可用时，原有虚拟操作继续正常执行，仅不显示标签组。分组失败不能把已经完成的页面动作变成失败，也不能触发页面动作重放或强制安装。

操作环境面板显示连接状态，未连接时提供“下载配套扩展”链接。下载由当前 Harness 的已认证本机地址 `/api/qiuya-tools.browser-extension.zip` 提供，仅当前所有者可用，不依赖第三方下载站点。解压后在浏览器扩展管理页选择“加载已解压的扩展程序”即可；不安装不影响电脑操控。Host 同时将配套文件复制到当前 profile 的 `qiuya-computer/browser-extension/`，便于本地测试。扩展权限用于读取标签身份和维护任务组，不注入网页脚本，不读取页面正文或使用系统鼠标；仅连接本机 `127.0.0.1:47931`，不向外部服务上传浏览记录。

分组只匹配当前授权窗口的几何信息和唯一标签标题。同名标签或窗口身份不明确时不分组；用户已有分组或手动改名后的分组不会被改写。当前任务打开且带有已受控父标签的子标签可以继承任务组，无关的新标签不自动加入。此版本真实浏览器分组验收针对 macOS Chrome；Windows 通用虚拟指针已编译，但 Windows 浏览器分组没有实机验收。

## 输入兼容

以下底层键鼠参数用于经过单次真实输入授权的原生动作；虚拟路径不支持的参数先走上述授权流程。

原生 `key` 和 `click` 支持 `holdMs: 1..2000`，默认 50ms。Windows 按键默认使用目标键盘布局的扫描码，`inputMode: standard` 可选择虚拟键码；扩展键 E0 标志随按下、释放和守护恢复保存。macOS 默认定向到进程，`inputMode: compatibility` 选择当前会话事件路径，按下与释放沿同一路径投递。

`moveRelative` 接受 `deltaX/deltaY`，单轴上限 4096，必须非零且不能混入绝对坐标。开始时指针和预计终点都必须位于已观察窗口内；Windows 使用相对鼠标事件，macOS 同时设置位置和位移字段。鼠标加速和目标客户端捕获方式仍可能影响实际效果，执行后应重新观察。

新参数必须由执行器声明 `inputCompatibility` / `input-compatibility`；旧执行器明确拒绝。浏览器执行器支持有界按住时长，拒绝原生专属输入模式与相对移动。取消、暂停和故障只释放当前所有者持有的输入。新格式恢复日志使用版本 2，旧执行器会阻止接管而不会错误删除不认识的按键责任。

## 窗口与画面兼容

Windows 窗口和运行中应用目录用 `PROCESS_QUERY_LIMITED_INFORMATION`、`QueryFullProcessImageName`、进程创建时间取得稳定身份，避免为路径读取请求整个主模块访问权限。无法识别的窗口计数进入状态诊断，不将未知身份当成已授权应用。

观察保存窗口位置及 DPI，任一变化都要求重新观察。`PrintWindow` 返回失败或均匀画面时尝试可见桌面截图；回退前后都要求目标前台、完整位于桌面、且没有其他窗口遮挡。受保护画面仍可能无法捕获；不会用输入动作强行刷新画面，也不会截取遮挡窗口冒充目标内容。

macOS 捕获流在显示缩放变化后重建。明确选择会话键盘兼容模式且 AX 根窗口属性不可用时，可用前后两次 CG 身份确认替代：目标必须是唯一的同进程可见普通窗口、位于普通窗口前列、进程与几何不变。已读到不同 AX 焦点、同进程多窗口歧义和暂时性 AX 超时均不走此替代路径。

## 远程与虚拟机兼容

操作本机远程桌面或虚拟机客户端时，先暂停任务，再在内嵌或独立预览中切换“标准输入 / 兼容输入”。设置只属于当前任务，切换会废弃旧观察；继续并重新观察后，后续键盘和文本沿所选路径发送。不会按应用名称匹配，也不会自动用另一种方式重发已有输入。客户端本身的键盘捕获、受保护输入或虚拟机集成设置仍须在实际环境验证。

通过远端 Agent 操作时，系统权限请求按聊天/任务的实际环境路由，不再打开本机权限设置。管理员访问只在目标机器请求，要求目标输入已释放，并由目标机器用户确认 UAC。macOS 权限仍在目标机器手动开启；浏览器环境不会被当作原生桌面提权。

远端输入回执丢失返回 `REMOTE_ACTION_UNCONFIRMED`，立即停止心跳和后续输入、尝试释放原租约，并要求用户重新连接后观察实际结果。已收到的明确拒绝保留原错误，不冒充网络结果未知。权限请求结果未知同样要求重新连接。Windows 检查 WTS 会话是否激活；macOS 检查当前用户桌面是否解锁并位于控制台，避免把后台进程存活误报成桌面可操作。

退出时先确认普通和提权输入所有者已释放，再回收截图/窗口资源；截图资源退出较慢不会延后输入释放回执。诊断脚本跟随实际原生入口和公开错误码更新。

自动验证覆盖策略、管道、回环代理、单次投递、暂停释放、会话隔离、旧帧失效以及两端编译。它不等于对所有第三方客户端、GPU/受保护画面或物理设备输入的实机兼容承诺。真实桌面验收应分别覆盖普通/管理员目标、窗口/全屏客户端、不同缩放、连接中断、锁屏与会话恢复，并以目标系统中实际发生的效果为准。
