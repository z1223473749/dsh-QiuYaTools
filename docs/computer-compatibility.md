# 电脑操控兼容性

## 权限兼容

Windows 普通模式会在输入前读取目标完整性级别。高权限目标返回 `administrator-required`，不会把权限失败等同于窗口失效或自动重发。

用户先停止现有控制，再在电脑操控的系统权限区域选择“启用管理员访问”，并在目标 Windows 桌面确认 UAC。独立助手只开放状态、应用发现、观察、租约和输入；应用启动、任意命令及网页预览不进入提权进程。主界面和网页预览继续使用普通权限。

提权通道使用同一用户的随机命名管道，双向核验进程身份。取消 UAC 不改变普通模式。切换后需重新观察和获取控制；安全桌面、跨用户提权和受系统保护的目标不承诺可控。普通和提权助手共用桌面锁；输入日志允许正常的跨权限交接，守护进程继承输入所有者权限。退出必须确认提权助手已释放输入，否则保持故障状态。

验证：TypeScript 类型检查、权限入口与原生协议测试、生产提权传输的独立 .NET 行为测试、Windows ARM64 编译。传输测试不产生系统输入。真实 UAC、跨权限桌面输入和异常恢复仍需 Windows 交互环境验收。

## 输入兼容

原生 `key` 和 `click` 支持 `holdMs: 1..2000`，默认 50ms。Windows 按键默认使用目标键盘布局的扫描码，`inputMode: standard` 可选择虚拟键码；扩展键 E0 标志随按下、释放和守护恢复保存。macOS 默认定向到进程，`inputMode: compatibility` 选择当前会话事件路径，按下与释放沿同一路径投递。

`moveRelative` 接受 `deltaX/deltaY`，单轴上限 4096，必须非零且不能混入绝对坐标。开始时指针和预计终点都必须位于已观察窗口内；Windows 使用相对鼠标事件，macOS 同时设置位置和位移字段。鼠标加速和目标客户端捕获方式仍可能影响实际效果，执行后应重新观察。

新参数必须由执行器声明 `inputCompatibility` / `input-compatibility`；旧执行器明确拒绝。浏览器执行器支持有界按住时长，拒绝原生专属输入模式与相对移动。取消、暂停和故障只释放当前所有者持有的输入。新格式恢复日志使用版本 2，旧执行器会阻止接管而不会错误删除不认识的按键责任。

## 窗口与画面兼容

Windows 窗口和运行中应用目录用 `PROCESS_QUERY_LIMITED_INFORMATION`、`QueryFullProcessImageName`、进程创建时间取得稳定身份，避免为路径读取请求整个主模块访问权限。无法识别的窗口计数进入状态诊断，不将未知身份当成已授权应用。

观察保存窗口位置及 DPI，任一变化都要求重新观察。`PrintWindow` 返回失败或均匀画面时尝试可见桌面截图；回退前后都要求目标前台、完整位于桌面、且没有其他窗口遮挡。受保护画面仍可能无法捕获；不会用输入动作强行刷新画面，也不会截取遮挡窗口冒充目标内容。

macOS 捕获流在显示缩放变化后重建。明确选择会话键盘兼容模式且 AX 根窗口属性不可用时，可用前后两次 CG 身份确认替代：目标必须是唯一的同进程可见普通窗口、位于普通窗口前列、进程与几何不变。已读到不同 AX 焦点、同进程多窗口歧义和暂时性 AX 超时均不走此替代路径。
