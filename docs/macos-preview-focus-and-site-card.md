# Mac 预览焦点与网站授权卡片修复

本次改动解决两个可复现的问题，并把代码、构建产物和测试作为一个提交。

程序弹出 Mac 原生预览时，原先的 `makeKeyAndOrderFront` 会取得键盘焦点。在双聊天实测中，关闭该预览后，目标应用出现两个时间戳相同的鼠标按下回调。程序打开预览改用 `orderFront` 后，保持原来的焦点；用户仍可点击预览，使其成为键盘窗口并操作接管控件。没有修改鼠标事件的发送次数、去重逻辑或业务断言。

网站授权组件位于电脑设置面板的同级位置，原先使用了不存在的卡片类，也没有电脑面板的样式作用域。本次复用现有工具箱卡片和电脑控件样式，并补上卡片间距与可访问名称。撤销和刷新许可的行为保持不变。

## 验证

- 实际构建 Mac universal 的 Apple Silicon / Intel 两个切片；电脑组件 SHA-256 为 `69a23738beab5f363ab47efe8f1b887f16d12f339ff64781ec9568bc19b0bdb3`，会话窗口组件与上一候选一致。
- 三入口 JS 构建记录了 164 个实际输入；Host 和电脑代理输出保持一致，客户端输出为 `6d74450536d118caa94e5a8ee4b35166559f1096ba02ce247e7a47483ab04367`。
- 八组 TypeScript 检查通过；完整工作区快照的 169 个测试文件共 2153 项通过，失败、跳过和取消均为零。隔离目录首次缺少历史归档夹具的失败记录保留，补齐原始夹具后重跑；没有跳过该测试。
- 原双聊天十项实测使用与本次构建字节一致的电脑组件，全部通过，包括跨聊天收回预览时的一次按下、一次释放，关闭 A 只暂停 A，以及 B 继续输入。实验外层报告曾读取错误的顶层哈希字段；原失败保留，独立核验读取实际 `environment.helperSha256`，不重跑或改写输入证据。
- 新 Mac 完整包通过原十二项实际功能验收，包括真实 Host、聊天授权、预览画面、人工接管、窗口拖出、TXT 上传、计划批注、归档及文件交换。新网站卡片已在本轮真实界面截图中核对。
- 新 Mac 包通过官方插件管理命令安装到本机；19 个安装文件与归档逐一核对一致，Harness 正常退出后重新打开。
- 三个平台归档均通过原安装包校验，未提高 64 MiB 上限。Windows 的后续逐项界面、中文输入、双会话和真实模型结果独立记录，不能由构建通过推导。
