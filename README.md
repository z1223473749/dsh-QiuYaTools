# QiuYa 增强工具箱

给 DeepSeek Harness 加一点顺手的小功能。

当前开发分支为 **0.6.0-beta.1**：增加 Mac/Windows 原生组件、电脑操控、悬浮实时预览和浏览器专用通道。该版本尚未公开发布，请使用交付目录中匹配系统/架构的候选 tgz；下面的 npm/历史 Release 安装入口仍以公开版本为准。详见[电脑操控与候选包说明](docs/computer-use-guide.md)。

## 安装

本次 Windows 候选版请安装对应的 `dsh-qiuya-tools-win32-arm64.tgz` 或 `dsh-qiuya-tools-win32-x64.tgz`；步骤与架构选择见[安装包说明](docs/computer-use-guide.md)。下方 npm 包名和通用 `dsh-qiuya-tools.tgz` 下载入口保留为 Mac universal 分发，不包含 Windows 原生程序。

1. 打开 Harness 的 **插件 → 添加插件**。
2. 输入 npm 包名 **`dsh-qiuya-tools`**，点击安装。
3. 点击 **立即启用**，进入 **设置 → QiuYaTools**。

左下角账号菜单也有 QiuYaTools 入口。[查看 npm 包](https://www.npmjs.com/package/dsh-qiuya-tools)。

也可在“添加插件”中粘贴 GitHub 安装包链接：

```text
https://github.com/z1223473749/dsh-QiuYaTools/releases/latest/download/dsh-qiuya-tools.tgz
```

镜像源同步新版本可能稍有延迟。暂时找不到包或新版本时，可稍后重试、切换到 [npm 官方源](https://registry.npmjs.org/)，或使用上面的 GitHub 链接。

## 功能

| 功能 | 怎么用 |
| --- | --- |
| 长文本附件 | 粘贴长文本自动转为 TXT，默认 1000 个字符或 15 行，阈值可调。 |
| 会话独立窗口 | 右键打开，或把会话拖出列表；再次打开同一会话会唤起已有窗口。 |
| 批量归档 | Shift 连选、⌘ / Ctrl 多选后右键归档，也可归档工作区全部会话。 |
| 计划批注 | 选中计划文字添加评论，提交修改建议，保留输入框原有草稿。 |
| 会话菜单 | 右键置顶、手动标记已读 / 未读、复制标题 / 会话 ID / 工作目录路径、打开目录；工作区也可移到顶部。 |
| 提示词建议 | 回复结束且输入框为空时，根据当前会话推荐下一句，失焦仍保留。聚焦后按 **Tab** 填入、**Esc** 隐藏，可修改后手动发送。 |
| Q主题「鲸与海」 | 手绘鲸鱼与白发少年背景，搭配柔和的半透明界面，支持浅色、深色外观。 |
| 电脑操控 | 在聊天中直接说明任务，模型发现应用后向你申请授权；实时预览与控制留在当前聊天，随时暂停、接管、继续或停止。支持本机以及已配对的独立电脑/虚拟机。 |
| 浏览器通道 | Chrome/Edge 独立登录配置或用户提供的调试连接，按网站来源授权；支持截图坐标、选择器、导航与标签页操作。 |
| 电脑任务记录 | 在会话中建立检查步骤，查看进度、画面证据和历史结果；证据不足或操作结果未确认时保持待确认。当前候选仍在进行实际界面验收。 |
| 自动验收与模板 | 编辑检查清单、保存清单版本并在当前聊天再次验收；模型取得新画面后执行，独立检查保留原失败和新结果，可只读比较历史。 |
| 画面批注与网页诊断 | 将框选、箭头、元素样式建议和画面发回当前聊天；网页日志与网络元数据单独授权并限量收集。 |

六项原有增强默认开启，可单独开关，也可一键全选。Q主题和新增电脑操控默认关闭，分别设置。新功能不会因原有“全部启用”自动取得桌面权限。

提示词建议使用当前会话所选模型，会产生少量额外模型用量。

## 在聊天中使用电脑操控

在 **QiuYaTools → 电脑操控** 启用功能后，回到聊天直接说明要使用的应用与任务。日常本机任务无需手动关联聊天、预选窗口或先连接环境；模型会在当前聊天发现应用、申请授权，再调用观察与操作工具。

授权卡显示应用和操作理由，由你选择 **允许一次 / 始终允许 / 拒绝**。一次授权仅用于本次电脑任务；始终允许保存在当前 Harness profile，可以在工具箱中查看、添加或撤销。模型不能替你确认授权。Mac 原生应用控制缺少屏幕录制或辅助功能权限时，界面会列出缺项并提供系统设置入口；按提示开启实际承担权限的 Harness 或 `QiuYaTools Computer`，返回后刷新权限。独立浏览器通道使用网站来源授权，不要求 Mac 桌面录制或辅助功能权限。每张授权卡按对应设备和通道检查权限。Windows 检查实际交互桌面状态，独立电脑的权限在对应电脑设置。

当前聊天默认显示 **300×180** 的实时小预览，画面沿 X/Y 两轴铺满整个小框，显示完整目标，不留黑边；不同宽高比会分别缩放。鼠标悬停或键盘聚焦后才显示暂停、接管、继续、停止和弹出／收回控件。小框可在 Harness 窗口内移动；人工接管时，拖动画面用于被控应用，通过控件握柄移动小框。

点击 **弹出** 可同时保留聊天小框和独立大预览，点击 **收回** 关闭大预览并继续任务。隐藏预览控件、收回大窗口或切换聊天都会继续后台任务；**直接关闭大窗口会暂停对应聊天**。暂停撤销 AI 输入权，接管允许你通过预览操作目标，继续重新获取画面与输入权，停止结束本次任务。

人工操作期间会暂时禁用文字和Enter，完成并取得新画面后恢复，避免重复输入。操作失败会保留原因，正常刷新画面不会将其清掉；未确认的输入不会自动重放。

每个聊天分别保存环境、目标、任务授权和暂停状态，默认浏览器配置也按聊天隔离。不同远端电脑或独立浏览器环境可以并行；同一 Harness 连接内共享真实桌面的鼠标、键盘和焦点由各动作按顺序使用。需要浏览器或配对远端时，在当前聊天的 **高级操作环境** 中连接，无需为普通本机任务配置这些选项。

实际 AI 指针动作使用小号半透明灰色填充、细白描边和柔和灰色光晕的箭头；动作结束、暂停、停止或人工接管后隐藏。Mac 只有在系统能力确认可用时才临时隐藏原系统指针，并在让出控制时恢复；无法确认时保留系统指针。该标识不会永久更改系统鼠标主题，也不表示模型思考时一直占用桌面输入。完整说明见[电脑操控指南](docs/computer-use-guide.md)。

## 更新与兼容

在 **QiuYaTools → 版本更新 → 检查更新** 中查看正式发布版本。开发中的 `0.6.0-beta.1` 使用交付目录内的平台候选包，不把旧 npm 或 GitHub Release 当作本次开发版。安装或更新后先查看插件管理器的应用状态；明确要求重启时，完全退出并重新打开 Harness，原有设置保留。

当前适配 Harness **0.2.1-rc.2**。Mac 原生组件以 **macOS 13+** 为构建目标，包含 Apple Silicon 和 Intel；Windows 候选包分别提供 ARM64 与 x64 的自包含程序，按 Harness 进程架构选择，独立窗口需要 Microsoft Edge WebView2 Runtime。普通 Windows 用户使用本机功能不需要 PD；操作虚拟机或其他电脑时，需要对应系统中已登录的交互桌面和配对代理。候选包尚未完成正式开发者签名与 Mac 公证。

各系统、架构、旧系统、现有功能、模型、耐久和安装结果按包与组件哈希分别记录。ARM Windows 中运行 x64 程序的结果不等于原生 x64 硬件验收，universal 编译也不等于 Intel Mac 或最低系统已实机通过。参见[测试与交付证据](docs/computer-use-test-report.md)。

当前完整工作区已完成 TypeScript 检查与1976项直接回归，前台交接单元另完成218项相邻测试，三入口JS和三平台候选均通过构建与原64 MiB安装包限制。Mac最终整合候选已通过完整12项功能、5项安装与恢复、Chrome专用通道10项，以及真实DeepSeek的按钮确认、中文提交和拖动三任务。完整功能验收包含实际Host、原生窗口与拖出、聊天授权、已绘制预览帧、人工接管、真实TXT上传、计划批注、精确归档及8 MiB文件交换；39张界面截图和三张真实模型结果图已在仓库外复核。范围、版本与清理证明见[Mac最终候选验收](docs/macos-final-candidate-acceptance.md)。

自动验收、工作台、批注、网页诊断、临时样式反馈和模板版本对比已分别完成Mac实际SDK闭环；其中的确定性测试provider用于证明工具与图像运输。真实DeepSeek另使用当前账户的公开SDK进行实际图片任务，由独立测试驱动模拟“允许一次”，不宣称真人点过授权。Windows当前原生组件的52项基础与29项专属指针测试已完成，最终整合包ARM64工作台七项通过；其余Windows逐项界面、完整整包、长测和真实模型最终交付仍继续验收，结果不沿用历史包。详见[候选视觉与模型结果](docs/current-candidate-visual-and-model-acceptance.md)及[测试与交付报告](docs/computer-use-test-report.md)。

电脑操控需要支持图片输入的模型。原生操作使用前台鼠标与焦点；浏览器专用通道支持后台标签页操作。当前Mac实测环境为Apple Silicon；universal构建不等于Intel Mac或最低系统已实机通过，ARM Windows中的x64程序测试也不等于原生x64硬件。Excel专用加载项与macOS锁屏操控仍属于单独的完整对齐阶段，当前基础包不宣称已完全复刻Codex。

同一交互桌面同时只允许一个 QiuYaTools 原生执行器控制输入，包括不同配置与已配对的代理。执行器异常退出时，独立守护进程会根据输入记录尝试释放本插件按住的键与鼠标；新执行器也必须先完成旧输入恢复，系统拒绝清理时会阻止新控制。Windows 会检查系统是否接受释放事件；macOS 的事件接口没有键盘送达确认，验收依据权限、可读取的鼠标状态及受控应用实测，不能据此保证任意应用均已处理每个键盘事件。
